# ADR 0001 — チェックポイントはリポジトリ外部のオブジェクトストアに配置する

[English](../adr/0001-checkpoint-store-location.md)

**ステータス:** 承認済み（accepted）  
**日付:** 2026-08-23  
**置き換え対象:** 設計計画で挙げられていた「git shadow ref（シャドウref）」アプローチ  

## コンテキスト

可逆性レイヤーは、ユーザーやエージェントが観察できるいかなる状態も変更することなく、ワーキングツリー（gitで追跡されていないファイルを含む）を復元できなければなりません。

単なる意図ではなくテストとして定義された不変条件（Invariant）:

> prohairesis がアクティブな状態であっても、`git log --all`、`git status`、`git stash list`、`git branch -a`、reflog、`HEAD`、`for-each-ref` は、prohairesis を使用していない対照用リポジトリとバイト単位で同一の出力を生成しなければならない。

当初の計画では、ユーザーのリポジトリ内部の `refs/harness/sessions/<id>/<seq>` にチェックポイントのコミットを書き込むことが提案されていましたが、それが実際にユーザーから見えないまま維持できるかどうかは明確な不確実性として挙げられていました。

## 決定

**不可視のまま維持することはできません。リポジトリ内シャドウref設計は却下されました。**

`git log --all` は、`refs/heads` + `refs/remotes` + `refs/tags` だけでなく `refs/*` 全体をグロブ（glob）対象とします。`refs/harness/` 配下のチェックポイントrefは `git log --all` の出力や `for-each-ref` に現れてしまいます。これはユーザーのリポジトリに対する目に見える変更であり、最初のチェックポイント作成時点で不変条件に違反します（`tests/scenarios/spike-shadow-ref.sh` のラウンド1で実測）。

代わりに: **各セッションはリポジトリの外部にベア（bare）オブジェクトストアを持ちます**（場所: `~/.prohairesis/sessions/<session-id>/store.git`）。リポジトリ自身のオブジェクトデータベースは `objects/info/alternates` を通じて読み取り専用で借用されます。

```bash
GIT_DIR=<store> GIT_WORK_TREE=<repo> GIT_INDEX_FILE=<store>/prohairesis-index git add -A
tree=$(GIT_DIR=<store> ... git write-tree)
commit=$(GIT_DIR=<store> git commit-tree $tree -m ...)
GIT_DIR=<store> git update-ref refs/checkpoints/<seq> $commit
```

`.git` 内には何も書き込まれません。refも、indexも、reflogエントリも、configも書き込まれません。使い捨てのインデックスファイルが使用されるため、ユーザーのインデックスが読み取られたり書き込まれたりすることは決してありません。

## 影響と結果（Consequences）

**利点（Good）:**
- 不変条件が維持されます。スパイクのラウンド2において、破壊的シナリオ（`rm -rf src`、`.gitignore` の破損）後の復元を含め、観察可能な全領域で検証済みです。
- 変更のないBlobはコピーされるのではなくalternates経由で借用されるため、チェックポイントのコストはツリー全体のコピーではなく、およそ1回の `git add` 相当の処理量で済みます。
- ユーザーのリポジトリで `git gc --prune=now` が実行されてもチェックポイントは破壊されません。prohairesis が書き込んだオブジェクトはストア内に存在し、借用されたオブジェクトはユーザー自身の履歴から依然として到達可能であるためです。
- アンインストールが極めて容易かつ完全です — リポジトリ外部のディレクトリを削除するだけで済みます。`.git` 内にクリーンアップすべきものが存在しないため、アンインストールによってリポジトリが破損することはありません。

**欠点・受容されたトレードオフ（Bad, and accepted）:**
- alternatesはリポジトリのオブジェクトデータベースへの依存関係を作ります。ユーザーが履歴を書き換え（rewrite）、**かつ**ガベージコレクションを実行した場合、チェックポイントは借用したオブジェクトを失う可能性があります。したがって、復元処理ではオブジェクトの利用可能性を検証し、部分的なツリー復元を行うのではなく明確にエラー（fail loudly）とする必要があります。中途半端に復元されたワーキングツリーを暗黙のうちに生成してはなりません。
- リポジトリの移動や名前変更によってチェックポイントが孤立しないよう、ストアはパスではなくリポジトリの識別情報（identity）によって配置場所を特定する必要があります。

**本レイヤーの対象外（Out of scope for this layer）:** 無視ファイル（`data/` ディレクトリ、ビルド成果物、ローカル環境設定ファイルなど）は、設計上 `.gitignore` を尊重するgitレイヤーからは意図的に除外されています。これらはCoW（コピーオンライト）スナップショット基盤によってカバーされ、巨大なファイルはコピーではなく書き込み拒否によって保護されます。計画の境界クラス B2 および B3 を参照してください。

## 検証（Verification）

`tests/scenarios/spike-shadow-ref.sh` — 12個のアサーションすべてに合格。将来再びリポジトリ内設計が再提案されないよう、ラウンド1の却下結果がヘッダーにドキュメントとして記録されています。
