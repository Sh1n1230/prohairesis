# テーゼ（Thesis / 基本理念）

[English](../THESIS.md)

> 人間はエージェントをマイクロマネジメントしない。
> 人間はエージェントが行動できる環境を設計する。

これはコーディングエージェントを安全に利用するための設定パックではありません。アクションによる危険で不可逆、かつ検証不可能な**影響（effects）**をシステムレベルで吸収することにより、エージェントが**最大限のエージェンシー（主体性・決定権）**を保持できるようにするためのマシンレベルの基盤です。

---

## 1. 混同してはならない4つの用語

| 用語 | 定義 | 設定主体 | 本プロジェクトのスタンス |
|---|---|---|---|
| **能力（Capability）** | エージェントが*物理的に実行できること* | OS、インストール済みツール、サンドボックスプロファイル | 最低限の基準（床）を寛容に設定。境界でのみ絞り込む。 |
| **主体性（Agency）** | エージェントが*尋ねることなく決定・選択・変更できること* | ポリシー、および**プロンプト（確認）の不在** | **最大化する。** すべてのコンポーネントは、エージェンシーを向上させるか中立であることを正当化しなければならない。 |
| **自律性（Autonomy）** | 人間の介入なしにどれだけ長く稼働し続けられるか | 創発的（H1を参照） | 境界を緩めるのではなく、検証と回復（リカバリ）によって向上させる。 |
| **ハーネス（Harness）** | コンテキスト、ツール、権限、検証、メモリ、フィードバック、ロールバック、可観測性 | 本プロジェクト | 手綱（leash）ではなく、環境。 |

## 2. 作業仮説 H1 — *証明された法則ではない*

```
H1:  自律性（Autonomy）  ≈  主体性（Agency） × 検証（Verification） × 永続状態（Persistent State） × 回復（Recovery）
```

設計はこの仮説に賭けています。率直に述べると:

- **主張**: これは*乗法（掛け算）的*であるということです。いずれかの要素がほぼゼロであれば自律性もほぼゼロになり、モデルの能力を向上させてもそれを補うことはできません。
- **反証条件**: 「永続状態」と「回復」を約0から1に引き上げても、ベースラインと比較して `mean_uninterrupted_run`（平均無中断稼働時間）が実質的に改善しない場合、H1は誤りであり、自律性は結局のところ主にモデル能力の関数であったことになります。その場合の正しい対応は、本プロジェクトを可逆性および監査レイヤーのみに縮小することです。これは隠すべき失敗ではなく、正当な結論です。
- **H1に依存しないもの**: 可逆性と可観測性は単体でも有用です（壊れたものを元に戻せる、何が起きたかを確認できる）。この賭けは後のレイヤーの*優先順位*に関わるものであり、プロジェクトの存在意義そのものに関わるものではありません。

## 3. 2つの中心思想

### (1) パーミッションプロンプトは不可逆性に対する価格設定メカニズムである

現在エージェンシーが制限されているのは、影響を回復できないからです。影響を回復可能にすれば、人間が勇気を出して「はい、今後は尋ねないでください」をクリックしたからではなく、価格（確認の手間）は**自動的**にゼロに下がるはずです。

> **設計原則: 人間の目に入るすべてのプロンプト（確認）は、ハーネスに関するバグ報告である。**
> 影響が内部に封じ込められているべきだったか、あるいは真に不可逆な外向きのアクションに属しているかのどちらかです。後者の場合、プロンプトは正しく、かつ極めて稀であるべきです。

### (2) 問題は「メタ認知の欠如」ではない。「外部基盤の脆弱さ」である。

```
タスク → 試行 → 失敗 → 試行 → 失敗 → 「これを解決できません」
```

エージェントは自身のプロセスについて推論する能力がないわけではありません。時点 *T* において、自分が何を試したか、どれだけの時間を費やしたか、どの仮説を除外したかを把握していました。しかし時点 *T+n* になると、能力を失ったのではなく、単に参照（記憶）を失ってしまったのです。

> **したがって、構築すべきは巨大な新しいAIシステムではない。**
> 既存のエージェントが忘れてしまう情報を保存するための、構造化された外部の場所である。

## 4. エージェントを制御すること vs. 環境を制御すること

これは単なる程度の差ではありません。

| | エージェントの制御（プロンプト、ルール、スキル） | 環境の制御（ポリシー、チェックポイント、状態） |
|---|---|---|
| 単位 | ツール呼び出しごとの個別の決定 | すべての呼び出しにわたる不変条件（Invariant）またはアフォーダンス |
| タイミング | 事前 — 何が危険かを予測しなければならない | 事後許容（Posterior-tolerant） — 事後に境界を設けるか取り消す |
| 失敗モード | **静か（Silent）。** 不服従が服従のように見える | **明確（Loud）。** 拒否されたアクションは観察可能なイベントとなる |
| モデル依存性 | モデルの世代交代によって劣化する | モデルやプロバイダーを越えて不変 |
| 合成性（Composition） | ルール同士が衝突し、累積し、腐敗する | 境界同士が交差し、単調（monotone）かつ検証可能 |
| エージェンシーへのコスト | 高く拡散的 — 安全なアクションまで狭めてしまう | 境界に集中し、境界内部ではゼロ |

具体的なテスト: 「エージェントに `rm -rf` を実行しないよう指示する」対「書き込み可能な集合はワークスペースであり、その直前の状態は復元可能である」。前者は `python -c "import shutil; shutil.rmtree(...)"` やサブエージェント、Makefile、そして指示を異なる形で解釈するモデルのアップデートに敗北します。後者はどのように削除が行われたかを気にしません。

> **設計原則: 環境の不変条件またはアフォーダンスとして表現可能なものは、プロンプトの指示として決して記述してはならない。**

**重要な系（Corollary）。** 環境を制御するとは、単に制限することを意味するだけではありません。メモリ、時間、状態、トポロジーは*環境が提供するアフォーダンス*です。エージェントに「試したことを覚えておけ」と指示することはエージェント制御であり、確率的で、コンテキストを消費し、コンテキスト圧縮によって消去されます。エージェントが試したことをクエリ可能な場所に存在させることは環境制御であり、決定的で、コンテキストを消費せず、圧縮を生き延びます。**メタ状態レイヤーはエージェンシーを向上させるものであり、制限するものではありません。**

## 5. ハーネスがエージェンシーを損なうなら、それは設計の失敗である

スローガンではなく運用上のコミットメントとして保持されます:

1. **デフォルト非ブロック（Default-non-blocking）:** いかなるコンポーネントもデフォルトで拒否してはならない。拒否には名前付き境界クラスへの所属が必要。それ以外のものは最大でも*記録*にとどめる。
2. **摩擦予算（Friction budget）:** すべてのコンポーネントはその摩擦コストを宣言する。実測された摩擦がその正当性を超えるコンポーネントは、**調整されるのではなく削除される**。
3. **回帰ゲート（Regression gate）:** 対応する回復イベントなしに人間の割り込みや注入コンテキストが増加した場合、それは本プロジェクトの回帰（デグレ）であり、`prohairesis doctor` で失敗とする。

このようなプロジェクトの自然な傾向は、エージェントの行動を阻止するための非常に高度な手段へと変質してしまうことです。計測だけがその迷走を防ぐことができるため、計測機能は最後ではなく初期段階で提供されます。

## 6. AIを信頼せずに大きなエージェンシーを付与できるか？

部分的には可能です — そしてその境界は明確です。

**信頼なしで可能:** 自身が制御し復元できる境界内にすべての足跡が収まる影響（ワークスペースへの書き込み、プロセスの生成、ローカル状態、ローカルにとどまるgit操作）。そこでの安全性は基盤の特性であるため、最大限に敵対的なエージェントに対しても成り立ちます。

**信頼なしでは不可能:** 残る3つのクラス:

1. **外向きの影響（Outward-facing effects）:** 金銭、使用されたシークレット、送信されたメッセージ、公開された成果物、変更された本番システム。いかなるローカル基盤も送信を取り消すことはできません。信頼を必要としない唯一の手段は、能力を与えないこと、**アクションを可逆的な代替物に変換すること**（共有refの代わりにブランチ、送信の代わりに下書き、適用の代わりに計画、本番キーの代わりにテストキー）、または人間にゲートを設けることです。第4の選択肢はありません。
2. **データ流出（Exfiltration）:** シークレットを読み取り、それを送信トラフィックにエンコードすることは、可逆でもなければスナップショットで検出することもできません。これはネットワークレイヤーおよびシークレットマスキングレイヤーで解決するか、まったく解決できないかのどちらかです。
3. **本プロジェクト自身のコントロールプレーン:** インプロセスフックは、任意のシェルを実行するプロセスを制約できません。カーネルレイヤーのみが敵対的な意図に耐えられます。

封じ込め可能で可逆なクラスこそがエージェントのアクションの圧倒的多数を占める領域であり、今日のパーミッションプロンプトのほぼすべてを生み出しています。**そのクラスからプロンプトを排除することこそが、本プロダクトのすべてです。**
